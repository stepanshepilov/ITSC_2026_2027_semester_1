# 1. DQN: аппроксимация Q-функции

## 1.1. От таблицы к нейросети

В табличном Q-Learning значение хранится для каждой пары `(state, action)`. Для больших или непрерывных пространств состояний таблица становится непрактичной. DQN заменяет таблицу нейросетью:

$$Q(s, a; \theta) \approx Q^*(s, a).$$

Для дискретного action space сеть получает observation и возвращает вектор Q-values размера `n_actions`. Выбранное действие:

$$a_t = \arg\max_a Q(s_t, a; \theta).$$

В CartPole observation состоит из четырёх чисел, поэтому подходит небольшой MLP. Для изображений вместо MLP обычно используют CNN.

## 1.2. TD-target и Huber loss

Переход из replay buffer имеет вид `(s, a, r, s_next, terminated, truncated)`. Для неоконечного перехода target равен:

$$y_t = r_t + \gamma \max_{a'} Q(s_{t+1}, a'; \theta^-).$$

Если эпизод завершён, bootstrap-часть обнуляется:

$$y_t = r_t.$$

Параметры online-сети `theta` обновляются по Huber loss между `y_t` и `Q(s_t, a_t; theta)`:

$$L(\theta) = \operatorname{Huber}(y_t - Q(s_t, a_t; \theta)).$$

Huber loss квадратична для малых ошибок и линейна для больших, поэтому отдельный большой TD-error меньше разрушает обновление, чем MSE.

## 1.3. Replay buffer

Последовательные переходы сильно коррелированы. Replay buffer хранит последние `capacity` переходов, а обучение использует случайную mini-batch выборку. Это:

- уменьшает корреляцию между примерами;
- позволяет повторно использовать опыт;
- делает обучение более похожим на i.i.d. оптимизацию;
- добавляет гиперпараметры `capacity`, `batch_size` и `warmup_steps`.

Слишком маленький buffer быстро забывает полезные переходы и даёт высокую дисперсию. Слишком большой buffer может содержать устаревший опыт, особенно если policy изменилась.

## 1.4. Target network

Если online-сеть одновременно вычисляет prediction и target, target движется при каждом обновлении. Это создаёт опасную обратную связь и нестабильность. DQN использует копию `target_net` с параметрами `theta^-`, которые обновляются раз в `target_update_frequency` шагов:

```python
target_net.load_state_dict(online_net.state_dict())
```

Частое обновление быстрее адаптируется, но усиливает нестабильность. Редкое обновление стабильнее, но target устаревает.

## 1.5. Epsilon-greedy

В начале обучения агент исследует среду:

$$\epsilon_t = \max(\epsilon_{min}, \epsilon_0 \cdot decay^t).$$

С вероятностью `epsilon` выбирается случайное действие, иначе `argmax Q`. Сохраняйте epsilon в логах: по одной только reward curve трудно понять, агент учится или перестал исследовать.

## 1.6. Target leakage и корректный done

`terminated` означает естественное терминальное состояние, а `truncated` обычно означает ограничение времени. Для базового учебного эксперимента можно считать оба случая концом эпизода, но в строгом bootstrapping важно не путать внешнее ограничение времени с настоящим terminal state.

Критические проверки:

1. target считается под `torch.no_grad()`;
2. действие индексирует только Q-value выбранного action;
3. target network не получает градиенты;
4. `done` корректно обнуляет bootstrap;
5. evaluation выключает exploration.

## 1.7. Диагностика

Полезные метрики: средний return, длина эпизода, epsilon, средний absolute TD-error, Q-value scale и доля успешных эпизодов. Если Q-values растут намного быстрее reward, ищите ошибку в done-mask, reward scale, learning rate или target update.
