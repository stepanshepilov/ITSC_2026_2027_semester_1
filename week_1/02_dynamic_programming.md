# 2. Dynamic Programming: Value Iteration и Policy Iteration

## 2.1. Предпосылка

Dynamic Programming (DP) работает, когда модель среды известна: для каждой пары `(s, a)` доступны вероятности переходов и награды. Это **model-based** подход: агент не собирает опыт для оценки переходов, а планирует непосредственно по модели.

## 2.2. Value Iteration

Value Iteration многократно применяет оптимальное уравнение Беллмана:

$$V_{k+1}(s) = \max_a \sum_{s'} P(s'|s,a)[R(s,a,s') + \gamma V_k(s')].$$

После сходимости policy извлекается как:

$$\pi(s) = \arg\max_a \sum_{s'} P(s'|s,a)[R(s,a,s') + \gamma V(s')].$$

Практический критерий остановки:

$$\max_s |V_{k+1}(s)-V_k(s)| < \theta.$$

### Псевдокод

```text
V(s) = 0 for every non-terminal state
repeat:
    delta = 0
    for s in states:
        V_new = max_a expected_return(s, a, V)
        delta = max(delta, abs(V_new - V[s]))
        V[s] = V_new
until delta < theta
policy[s] = argmax_a expected_return(s, a, V)
```

## 2.3. Policy Iteration

Policy Iteration чередует два шага:

1. **Policy evaluation:** оценить `V^pi` для текущей policy.
2. **Policy improvement:** заменить действие на лучшее согласно текущей value function.

Алгоритм останавливается, когда улучшение не меняет ни одного действия.

Policy Iteration часто делает меньше внешних итераций, но evaluation может быть дорогим. Value Iteration делает более грубое обновление и обычно проще для первой реализации.

## 2.4. GridWorld

Для учебной среды задайте:

- прямоугольную сетку;
- стартовую клетку;
- терминальную клетку с положительной наградой;
- препятствия;
- штраф за каждый шаг;
- вероятность случайного отклонения от выбранного действия.

Хороший минимальный benchmark должен проверять не только достижение цели, но и то, что агент умеет обходить препятствия и предпочитает короткий путь.

## 2.5. Что измерять

- число итераций до сходимости;
- значение стартового состояния;
- длину greedy-траектории;
- суммарную награду;
- изменение поведения при увеличении `slip_probability`.

## 2.6. Типичные ошибки

- обновлять терминальное состояние так, будто из него есть обычные переходы;
- перепутать награду за переход и награду за вход в состояние;
- использовать старую value function для одного действия и уже обновлённую для другого без явного выбора варианта обновления;
- забыть, что при `gamma < 1` длинные маршруты штрафуются сильнее.
